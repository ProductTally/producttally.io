¿Por qué no se activa Error Trigger en n8n? Comprueba la ejecución y la alerta

Vincula el flujo de errores, provoca un fallo controlado y usa el historial para localizar dónde se interrumpe la notificación.

Por Evan · Actualizado 13 nov 2026

En esta página

  1. Respuesta rápida
  2. Vincula el flujo de errores a un flujo de prueba
  3. Compara una ejecución manual con una automática

Respuesta rápida

Si Error Trigger no se activa, comprueba si el flujo de origen se ejecutó automáticamente y si apunta al flujo de errores correcto. Un fallo en una ejecución manual no activa Error Trigger. Usa un flujo desechable y un destino de notificación de prueba.

Reseña de n8n

Vincula el flujo de errores a un flujo de prueba

Crea un flujo aparte que empiece con Error Trigger y envíe un aviso a un buzón de prueba. Incluye el nombre del flujo y el enlace a la ejecución cuando esté disponible. En el flujo desechable, coloca Stop And Error tras un disparador automático como Schedule Trigger. Selecciona el flujo de errores en los ajustes y habilita el origen.

Compara una ejecución manual con una automática

Provoca primero el fallo manualmente. Debes verlo en el editor sin recibir la alerta de Error Trigger. Deja que el horario lance una ejecución y comprueba tanto el fallo del origen como la ejecución del flujo de errores. Revisa la hora y la referencia del aviso y desactiva el horario de prueba.

Localiza dónde se interrumpió la alerta

Si no hay ejecución automática, revisa la activación y el disparador. Si el origen falló y el flujo de errores no se ejecutó, comprueba el vínculo y el modo de ejecución. Si se ejecutó pero no llegó el aviso, inspecciona el nodo de notificación. Una salida vacía puede necesitar su propia condición si tu equipo debe tratarla como fallo.
