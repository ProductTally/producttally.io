Datos fijados en n8n: cómo usar una muestra sin cambiar la ejecución real

Desarrolla el siguiente nodo con un formulario ficticio y distingue la entrada de producción.

Por Evan · Actualizado 23 nov 2026

Fija datos si quieres reutilizar la salida de un nodo en el editor de n8n. Las ejecuciones de producción ignoran esos datos y procesan la entrada del momento. Una solicitud ficticia permite compartir el ejemplo sin copiar datos de clientes.

n8n · Ver detalles del producto

Elige una muestra que explique el flujo

Un formulario de un estudio recibe tipo de proyecto, idioma y fecha. Prepara una solicitud con projectType igual a newsletter, language igual a es y una fecha ficticia. Sirve para explicar por qué el registro llega a la cola del boletín en español.

Sigue la documentación de n8n para fijar la salida de un nodo compatible. En el editor, los nodos posteriores pueden trabajar con la misma entrada. Así puedes ajustar el enrutado o el mensaje sin esperar otro envío.

  • Ayuda de n8n · usar una salida representativa

Aclara qué estás comprobando

Para cambiar la lógica de la cola, la muestra conocida resulta útil. Para comprobar si el formulario cambió el nombre de un campo, desfija los datos y usa una entrada nueva. De otro modo seguirás viendo el formato anterior.

Indica qué nodo contiene la muestra, qué campos incluye y qué variante conviene considerar, por ejemplo una solicitud sin idioma. Excluye credenciales, contactos y notas de clientes.

  • Ayuda de n8n · usar una salida representativa

Identifica la entrada de una ejecución real

Cuando el flujo activo reciba un formulario, usará los datos del evento real. La muestra fijada se queda en el editor. Antes de publicar cambios, confirma la cola o destino de producción, en especial si el flujo envía avisos o escribe en un sistema compartido.
