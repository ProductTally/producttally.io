Procesa peticiones por lotes en n8n con Loop Over Items y Wait

Importa una hoja de cálculo al ritmo que permite la API de destino.

Por Evan · Actualizado 24 nov 2026

Usa Loop Over Items y Wait para repartir lotes cuando la API tiene una cuota de peticiones. Retry On Fail sirve para interrupciones breves. Calcula el límite del servicio y cuántas peticiones genera cada fila.

n8n · Ver detalles del producto

Cuenta las peticiones de cada fila

Imagina que importas 100 productos aprobados a un catálogo. Si cada fila requiere una escritura y la API permite 60 por minuto, un lote de 10 cada 15 segundos equivale a unas 40 escrituras por minuto, antes de contar otros flujos. Una consulta previa por fila consume más si comparte la cuota.

Consulta la documentación del destino. La cuota puede ser por credencial o por ventana móvil. Deja margen para otros flujos. Si aparece un 429, revisa el límite y cómo se concentran las peticiones.

  • Documentación de n8n · lotes y límites de la API

Deja preparada la reanudación

Conecta el lote a la petición y vuelve al bucle pasando por Wait. Reserva Retry On Fail para interrupciones breves cuando repetir sea seguro. Para operaciones de alta, usa una clave estable o un upsert si el destino lo admite.

Guarda el resultado por registro y reintenta solo los pendientes. Si una respuesta agotó su tiempo, comprueba el estado del catálogo antes de volver a crear el registro.
