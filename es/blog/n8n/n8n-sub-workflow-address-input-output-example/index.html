¿Cuándo conviene compartir una comprobación de direcciones entre dos flujos de n8n?

Reutiliza una comprobación de campos de dirección y devuelve al flujo principal un resultado que pueda usar.

Por Evan · Actualizado 18 nov 2026

Un formulario web y una herramienta de soporte pueden necesitar los mismos campos de dirección. Extrae la comprobación a un subflujo de n8n. Cada flujo principal puede decidir si continúa, pide que se complete un dato o guarda el pedido. Si solo hay un flujo que usa la comprobación, suele ser más fácil mantenerla allí.

Define qué significa el resultado

Pasa requestId, countryCode, city y line1. Quita los espacios al principio y al final y devuelve requestId, status y missingFields. Que los campos estén presentes no garantiza que el transportista pueda entregar un paquete. Los demás datos del pedido pueden quedarse en el flujo principal.

Define las entradas en Execute Sub-workflow Trigger. En el flujo principal, selecciona el subflujo guardado en Execute Sub-workflow y asigna los cuatro valores. Activa Wait for Sub-Workflow Completion si el flujo principal necesita el resultado. n8n devuelve los datos del último nodo del subflujo. Ejecuta ambos ejemplos y confirma que las dos ramas devuelven los mismos campos.

Distingue los campos ausentes de los errores de ejecución

Si falta la ciudad, puedes pedir al usuario que la complete o crear una tarea para soporte. Si falla un nodo o faltan permisos, conserva el error de ejecución para investigar. Cuando otro flujo necesite verificar que se puede entregar en esa dirección, añade una comprobación aparte con una fuente adecuada.

Prueba también un valor nulo. Una entrada sin asignar puede llegar como null. Trata tanto null como una cadena de solo espacios como un campo ausente y devuelve las mismas claves. Si falta requestId, registra un error de entrada, ya que el flujo principal no puede reconciliar la respuesta.
