Windsor.ai: Why do the ad reports add up to more than the store took in?

Use two orders to compare store sales and overlapping platform attribution, then choose a consistent reporting grain.

By Evan · Updated Nov 18, 2026

Keep store order revenue separate from attributed revenue. Windsor.ai's Blended Data connector queries connected sources through one endpoint. Decide whether each row represents an order, a channel-day or a platform-attributed conversion. Multiple ad platforms can claim one sale and use different lookback windows.

  • Windsor.ai Blended Data connector

When you export from the Blended Data connector, keep the source field alongside the date and amounts so you can identify the original connector for each row. Check whether each source exposes an order ID before designing a join.

In this fictional data, attributed revenue adds up to 210 while orders add up to 130. Both platforms claim A001. For order-level data, key records by store and order ID. Reconcile multiple line items, refunds and currency before summing. A short order number can recur across stores. GA4 uses unique transaction IDs to reduce duplicate purchase events, but that doesn't deduplicate several separate platform reports.

  • Google Analytics transaction IDs

Keep daily ad-platform totals separate

Without shared order IDs, show each platform's totals by date, account, currency and attribution window. Label platform-attributed revenue and store revenue separately. Specify which figure goes into ROAS. Summarize orders and spend separately at a compatible grain before joining, then check whether the join repeats any amount. Test one known overlapping order where possible. Verify refund handling and time zones before the report goes live.
