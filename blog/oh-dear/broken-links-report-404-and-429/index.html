Oh Dear broken-link reports: fix internal 404s and handle external 429s

Triage a post-redesign crawl by source page and destination, and know when to use an exclusion.

By Evan · Updated Nov 23, 2026

Use the source page in an Oh Dear broken-link report to find and edit an internal link that returns 404. A third-party 429 may be a rate limit for automated requests. Confirm the destination works for visitors before excluding a specific URL from reports.

Oh Dear · View product details

Fix the page that still points at the old URL

A pricing redesign moves /plans/ to /pricing/. The homepage is already updated, but an old onboarding guide still points to /plans/. Find the source page in the report and change that link to /pricing/. Check other pages that share the same footer or template, since they may all be using one outdated anchor.

If the old URL was public, consider whether external links or bookmarks still need a redirect. Use the new page directly in your own navigation so visitors do not need to make the extra hop.

Treat an external 429 as a different investigation

A partner’s social site might serve visitors while rate-limiting a crawler. Open the reported destination in a regular browser and verify that it reaches the expected page. If people can open it and Oh Dear consistently encounters a crawler limit, document the reason and add a narrow pattern under Settings → Broken Links → Ignored URLs.

Oh Dear says Ignored URLs suppresses reporting but still allows visits by its crawler. Do not crawl is the separate list for paths the crawler should never request. One URL pattern is usually easier to maintain than a wildcard covering an entire host.

Run the next report against the issue you actually fixed

Check whether the same source page still appears with the old destination. If several pages surfaced one shared footer issue, resolve the template and look for those reports to clear together. Keep the exception for an external site separate from the list of changes to your own HTML.
