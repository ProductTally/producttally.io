n8nの二つのワークフローで、住所チェックを共通化するなら？

住所の必須項目チェックを共通化し、親ワークフローから値を渡して結果を受け取ります。

によって Evan · 更新日 2026/11/18

Webフォームとサポート用の注文登録で住所の必須項目が同じなら、そのチェックをn8nのサブワークフローに切り出せます。手続きを進めるか、入力を促すか、注文を保存するかは親が決めます。利用するワークフローが一つなら、その中に残す方が処理を追いやすいこともあります。

結果が何を表すかを決める

親から requestId、countryCode、city、line1 を渡します。前後の空白を除き、requestId、status、missingFields を返します。ここで確認できるのは項目の有無です。配送可否までは判断できません。関係のない注文情報は親に残します。

A02、JP、都市名は空白のみ、住所1行目ありA02、`needs_input`、リストに `city

Execute Sub-workflow Trigger で入力項目を定義します。親の Execute Sub-workflow で保存済みの処理を選び、4項目を渡します。親が結果を使う場合は Wait for Sub-Workflow Completion を有効にします。n8nは子の最後のノードからデータを返します。2件とも実行し、どちらの分岐でも同じ項目名が返ることを確認します。

項目の不足と実行エラーを分ける

都市名の欠落なら、フォームで再入力を促すかサポートに作業を割り当てられます。ノードの異常や権限不足なら、担当者が調査できるように実行エラーを残します。配送可能な住所かどうかを確認する別の入口が加わった場合は、その目的に合うデータで別途検証します。

空白だけの値に加え、nullも試します。親でマッピングしていない入力はnullで届くことがあります。どちらも不足項目とし、同じキーで結果を返します。requestIdがなければ元の依頼と照合できないため、入力エラーとして扱います。
