フォームが再送されてもn8nの登録を1件に保つには？

再送でも同じ送信IDを使い、PostgreSQLの一意制約とパラメーター付きINSERTで記録を1件に保ちます。

によって Evan · 更新日 2026/11/18

フォーム側で再送時に元の送信IDを再利用し、PostgreSQLでそのIDを一意キーにします。最初の書き込みが成功していても、送信元が応答を受け取れずにWebhookを再送することがあります。n8nのPostgresノードからパラメーター付きのINSERTを実行すれば、同じIDに同じ制約が適用されます。

新規作成の判定をINSERTに任せる

  • n8nのPostgresノード
  • PostgreSQLのINSERTリファレンス

テスト用テーブルの submission_id をテキスト型の主キーにします。Query ParametersにIDと名前を $1、$2 の順に渡します。複数の送信元でIDが重なるなら、送信元とIDの組み合わせをキーにします。同じメールアドレスで別々の有効な申込が届くこともあります。IDがないデータは、書き込み前に拒否する分岐へ送ります。

WITH inserted AS (
  INSERT INTO form_entries (submission_id, submission_name)
  VALUES ($1, $2)
  ON CONFLICT (submission_id) DO NOTHING
  RETURNING submission_id
)
SELECT EXISTS (SELECT 1 FROM inserted) AS created;

新規なら created = true、既存なら false が返ります。先にSELECTだけを実行すると、二つの処理が同時に未登録と判断することがあります。主キーの制約なら挿入の時点で競合を処理できます。

行数と確認メールを別々に確かめる

テスト用の demo-42 を2回、別の demo-43 を1回送ります。同じIDを同時に送る場合も試します。期待する結果は2行で、demo-42 は1行だけです。IDの欠落や、別の送信元が同じIDを使う場合も確認します。

確認メールは新規作成の分岐だけで送ります。それでも、コミット後に処理が止まればメールは届きません。確認の取りこぼしを許容できない場合は、同じトランザクションで送信待ちのイベントを保存し、別の処理で送信と再試行を行います。登録件数とは別にメールの到達を検証します。
