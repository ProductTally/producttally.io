顧客がV1を保存済み。pCloudにV2を載せたら連絡する？

同名で更新した後に旧リンクとダウンロードを確認し、承認用の版は別に保管します。

によって Evan · 更新日 2026/11/18

連絡します。元の共有リンクで最新版を開けても、顧客が端末に保存したコピーは更新されません。pCloudの同じ場所でファイルを更新し、別のゲストセッションで元のリンクを開きます。プレビューと再ダウンロードを試し、リンクが無効、権限が違う、またはV1が出る場合は、確認した新しいリンクを送ります。

ファイルの1ページ目で版を判別できるようにする

  • pCloudのアップロード
  • pCloudの共有リンク

テスト用PDFを2つ用意し、V1には「レビュー用」、V2には「承認待ち」と書きます。

  1. テストフォルダーでV1を proposal.pdf として共有します。リンクとダウンロードしたコピーを残します。
  2. 同じフォルダーへ同じ名前でV2をアップロードします。上書きか別ファイルの作成かを確かめます。開発者向け資料では、同じフォルダーで同名のファイルを作成するとファイルIDを再利用し、以前の内容をリビジョンとして保存すると説明しています。利用中のWebやデスクトップでも確認します。
  3. 元のリンクを開き直し、ダウンロードして1ページ目がV2かを見ます。初回に保存したV1も残っていることを確認します。過去版を取り出す場合はアカウントの履歴を確認します。
  • pCloudのファイルID
  • pCloudの変更履歴

承認する版は別のファイルで残す

継続レビューなら「元のリンクはV2です。3ページ目を差し替えたので、保存済みのV1は更新してください」と伝えます。金額、作業範囲、公開の最終承認なら、版番号入りのファイルを別に保存し、その版を指定して承認を求めます。後から作業用のファイルを更新しても、どの版を承認したか確認できます。

ファイルIDの扱いは開発者向け仕様に基づきます。アップロードするクライアントで上書きできるか、元のリンクから何が表示されるかを別々に確かめます。承認用の版は別に保管し、プレビューと再ダウンロードの両方を試します。履歴はpCloudのWeb版で確認します。
