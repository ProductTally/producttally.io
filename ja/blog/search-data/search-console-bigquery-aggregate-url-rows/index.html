Search ConsoleのBigQueryエクスポートで同じURLが複数行あるのはなぜ？

集計単位を決めてクリック数と表示回数を合計し、CTRとデータ欠損を区別します。

によって Evan · 更新日 2026/11/19

Search Consoleの一括エクスポートには、同じキーの行が複数入ることがあります。日別のページ集計では、検索タイプを固定し、日付とURLでまとめてクリック数と表示回数を合計します。CTRには両方の合計を用います。Googleも各キーに属する数値を集計する方法を案内しています。

レポートの1行が何を指すかを決める

日別のページ集計にはsearchdata_url_impressionを使います。検索タイプと期間をそろえ、国別に見る場合はcountryをグループに加えます。プロパティ全体を集計する場合は、Googleが別のルールで集計するプロパティ用テーブルも検討します。データセット名とdata_dateの日付範囲を確認し、太平洋時間を基準にします。

CTRは合計してから割る

架空のデータで、あるURLに同じ日の20表示・4クリックと80表示・6クリックの行があるとします。合計は100表示と10クリックなので、CTRは10%です。2行の率を平均すると13.75%になります。BigQueryのSAFE_DIVIDEで集計後の数値を割り、分母が0のときは空欄にします。

SELECT data_date, url,
       SUM(clicks) AS clicks,
       SUM(impressions) AS impressions,
       SAFE_DIVIDE(SUM(clicks), SUM(impressions)) AS ctr
FROM `my_project.searchconsole.searchdata_url_impression`
WHERE data_date BETWEEN @start_date AND @end_date
  AND search_type = 'WEB'
GROUP BY data_date, url
ORDER BY data_date, clicks DESC

未出力の日付に印を付ける

週ごとに比較する前に、ExportLogで該当するテーブルと日付を調べます。ログには成功した出力が入り、URL用とプロパティ用のテーブルが同時に届くとは限りません。未取得の日付を欠損として記録し、期間がそろってから同じ検索タイプとグループで比べます。
