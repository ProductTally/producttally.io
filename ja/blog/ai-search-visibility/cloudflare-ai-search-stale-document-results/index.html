Cloudflare Search for Agents が古い文書を返すときの調べ方

公開ページからクロール、同期、検索キャッシュまで、古い検索結果の出どころをたどります。

によって Evan · 公開日 2026/11/28 · 更新日 2026/11/28

Cloudflare Search for Agents が古い案内を返したら、結果の引用先を開き、現在の本文と抜粋を照合します。そのうえでクロールと同期の履歴を確認し、必要に応じてキャッシュを調べます。機能のベータ公開は2026年11月25日です。

Search for Agents

まず引用先の URL を開く

デスクトップアプリの手順をバージョン2から3に改訂したとします。/.well-known/search に利用者の質問を入力し、時刻、引用先、バージョン2と書かれた一文を控えます。旧版のアーカイブが引用されているなら、バージョン3を明記して再検索します。現行ページの索引が古い場合と、別の旧版ページが見つかった場合を切り分けられます。

  • Search for Agents

同期完了の時刻と公開時刻を見比べる

Search for Agents の既定は Discover 方式で、クロールキャッシュの期限は24時間です。Discover は再取得の判断にサイトマップの lastmod を使いません。インスタンスの設定と Jobs の履歴を開き、デプロイ時刻と照らし合わせます。手動同期でも再クロールの条件は同じです。

  • クロール方式
  • 同期ジョブ

同じ質問で新しい抜粋を確認する

索引に更新が反映されたら、元の質問を使って引用先と文面を確認します。AI Search の公式資料では、cf-aig-cache-status の HIT と MISS でキャッシュを判別でき、索引内の該当チャンクが変更・削除されると関連するキャッシュが消去されると説明しています。返るのは検索で取り出した抜粋なので、掲載文と直接照合できます。
