คำตอบสั้น ๆ

Oh Dear รวมการตรวจความพร้อมใช้งานและความสมบูรณ์ของเว็บไซต์ เริ่มจากหน้าแรกที่ปกติและเป้าหมายวินิจฉัยแยกต่างหาก การทดลองสิบวันแบบไม่ใช้บัตรเมื่อ 10 พฤศจิกายน 2026 ตรวจพบ 404 ที่ตั้งใจสร้าง และพบผลปกติหลังเปลี่ยนเป้าหมาย โดยไม่ได้ซื้อแพ็กเกจ

รีวิว Oh Dear

เพิ่มเว็บไซต์ที่มีสิทธิ์ตรวจ

เพิ่มหน้าแรกและรอแต่ละการตรวจเสร็จ uptime, SSL และ DNS มาก่อนการรวบรวม URL กับ Lighthouse รอบนั้นรายงาน 126 URL และลิงก์เสียศูนย์รายการ เป็นผลครั้งเดียว ไม่ใช่การครอบคลุมทั้งหมด หน้าแรกยังปกติ

แยกประเภทการแจ้งเตือน

ได้รับทั้งข้อความทดสอบและอีเมลแจ้งลิงก์เสีย แต่ไม่พบอีเมล uptime ล่มและกลับมาปกติแยกต่างหาก อีเมลลิงก์เสียจึงไม่ยืนยันว่าแจ้งเตือนทุกประเภทตั้งค่าและส่งถึงแล้ว

อ่าน URL เต็มของ 404

มอนิเตอร์แยกที่ชี้ไปยังเส้นทางไม่มีอยู่ให้ HTTP 404 ขณะที่หน้าแรกยังปกติ ข้อความเด่นย่อเป้าหมายเหลือชื่อโดเมน ควรดู URL เต็ม รหัสตอบกลับ และเวลาก่อนสรุปว่าทั้งเว็บไซต์ล่ม

ตีความการกลับมาปกติ

เปลี่ยนเป้าหมายเป็น /guides/ แล้วตรวจอีกครั้งได้ HTTP 200 ช่วงปัญหาคือ 17:47:50–17:48:56 ตาม Asia/Shanghai นี่คือผลหลังเปลี่ยนเป้าหมาย ไม่ใช่การซ่อมระบบจริง แต่ละการตรวจอัปเดตแยกกันและอาจค้างผลก่อนหน้า

อ่านประวัติและการส่งออกอย่างมีบริบท

100% ใต้ป้าย 7/30 วันของมอนิเตอร์ใหม่ไม่ใช่การสังเกตครบสามสิบวัน Chrome ปิดกั้น CSV ด้วย ERR_BLOCKED_BY_CLIENT จึงไม่ได้ไฟล์ แต่ไม่ใช่หลักฐานว่าเซิร์ฟเวอร์ส่งออกเสีย หลังทดสอบปิดการตรวจสิบเอ็ดรายการของเป้าหมายวินิจฉัย โดยหน้าแรกยังตรวจต่อ
