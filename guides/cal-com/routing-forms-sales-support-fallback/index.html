Cal.com Routing Forms: separate sales from support before booking

Use three test responses to check route order, support handoff and the fallback destination.

By Evan · Updated Nov 16, 2026

On this page

  1. Quick answer
  2. Keep intake short
  3. Set the rules in order
  4. Submit three cases before embedding

Quick answer

In Cal.com Teams, set routing rules so an inquiry reaches the right booking link or support destination. Put specific rules first and test the fallback before embedding the form. This guide covers the intake form, with Round Robin available for host assignment after a booking route is selected.

Cal.com Review

Keep intake short

Use a fictional studio with a two-person sales team. Ask what the visitor needs, with options for a sales demo, existing-customer support and other. Only collect the fields the team needs. Prepare a demo booking link, a support contact page and a fallback page with clear next steps.

Set the rules in order

Send sales demos to the sales booking link. Send support requests to the support destination. Use the fallback for unmatched responses. If you add overlapping routes later, put the specific route above the broader one and test a response that qualifies for both.

Submit three cases before embedding

Demo should show the sales calendar, support should open the support page and other should reach the fallback. In a private browser window, record the response and actual destination for all three. Verify that a support request cannot land on the sales calendar. Re-run the same cases after changing routing order or destination links.
