n8n Error Trigger not firing? Check automatic runs and alert delivery

Bind an error workflow, trigger one controlled failure and use the execution record to locate the break in your alert path.

By Evan · Updated Nov 13, 2026

On this page

  1. Quick answer
  2. Connect the error workflow to a disposable source
  3. Compare a manual run with an automatic run
  4. Use the execution records to find the missing step

Quick answer

If an n8n Error Trigger never fires, check whether the source workflow ran automatically and whether its settings point to the right error workflow. A failure during a manual run does not invoke the Error Trigger. Use a disposable source workflow and a separate notification destination for the test.

n8n Review

Connect the error workflow to a disposable source

Create a separate workflow starting with Error Trigger and send a brief notification to a test inbox. Include the workflow name and execution link when available. In a disposable workflow, use an automatic trigger such as Schedule Trigger followed by Stop And Error with an obvious test message. Select the error workflow in the source workflow settings and enable the disposable source for automatic runs.

Compare a manual run with an automatic run

First run the source manually. Expect a failed run in the editor and no Error Trigger alert. Then let the schedule fire once. Verify that the source execution failed and that the separate error workflow ran. Check the notification timestamp and the included execution reference. Turn off the disposable schedule after the check.

Use the execution records to find the missing step

If no automatic source run exists, inspect its trigger and activation state. If the source failed and the error workflow has no run, recheck the association and whether the source was executed manually. If the error workflow ran but no message arrived, inspect its notification node. Empty results that are acceptable to n8n need a separate condition if your team wants them treated as failures.
