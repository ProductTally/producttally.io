Oh Dear for small websites: monitor uptime and diagnose broken links

Set up a homepage monitor and learn how to interpret a 404, a crawl report and a recovery alert.

Quick answer

Oh Dear suits small teams that want uptime, certificate checks and link crawling together. For a content site, the crawl is what helps you catch a broken guide or download while the homepage still works. Oh Dear brings availability and site-integrity checks into one place. For a small publisher, the useful starting point is a healthy homepage plus a separate diagnostic target. On November 10, 2026, a no-card ten-day trial detected an intentional 404 and reported a healthy response after the target changed. No plan was purchased.

Oh Dear Review

Start with the site you control

Add your authorized homepage and wait for each check to finish. Uptime, SSL and DNS results arrived before the crawl and Lighthouse run. That crawl reported 126 URLs and zero broken links; those figures describe one run, not complete coverage. The homepage monitor remained healthy.

Test delivery, then distinguish alert types

A test notification arrived, and a later broken-link failure email arrived too. These establish two observed email paths. We did not observe separate uptime-down or uptime-recovery emails, so do not treat the broken-link email as proof that every alert type is configured and delivered.

Read the full target behind a 404

An independent monitor pointed to a deliberately nonexistent path returned HTTP 404 while the homepage stayed up. The prominent report shortened the target to its hostname. Check the full URL, status and timestamp before announcing a domain-wide outage. A missing page is not evidence that the whole site is down.

Interpret recovery and check timing correctly

Changing that monitor’s target to the existing /guides/ page and checking again produced HTTP 200. The failure interval was 17:47:50–17:48:56, Asia/Shanghai. This was recovery after a target change, not repair of a production outage. Per-check results update independently; an old broken-link result can remain after uptime recovers.

Read history and exports with context

A newly created monitor’s 100% under a 7/30-day label is not 30 days of observed availability. Chrome blocked this session’s downtime CSV download with ERR_BLOCKED_BY_CLIENT, so no CSV was obtained. That does not establish a broken server-side export. All eleven checks on the diagnostic monitor were disabled afterward; homepage monitoring continued.

Choose a plan for your actual sites

The trial ends November 20. Official prices checked November 10 were Solo €15/month for 2 sites, Solo Plus €29 for 5, Freelance €49 for 10, Studio €99 for 25 and Agency €149 for 50, excluding VAT. This is a useful introduction to monitoring and diagnostics; Cron, public status pages and long-term reliability were not tested.

Pair public website checks with the alerts your team needs

In a Laravel community discussion, a Reddit commenter distinguished Oh Dear’s availability checks from the deeper diagnostics in Laravel Nightwatch. Pair outside-in checks with application error reporting if you need both views. Start by checking that Oh Dear can reach a page linked from your navigation. If a page can return HTTP 200 with the wrong content, the vendor documents a response-text check. Give login or checkout its own end-to-end check if that workflow matters to your business.
