How to set up a 301 redirect with SEOPress PRO after changing a WordPress URL

Map an old WordPress permalink to its replacement, then verify the HTTP response, internal links and sitemap.

By Evan · Updated Nov 13, 2026

On this page

  1. Quick answer
  2. Set the old path and new destination
  3. Verify the first response and the final page
  4. Update the references you control

Quick answer

Use a 301 redirect when the same article has permanently moved to a new URL. In SEOPress PRO, map the old relative path to the full new HTTPS URL. Verify that the old URL responds with 301 and sends readers directly to the replacement, which should respond with 200.

SEOPress Review

Set the old path and new destination

For this example, move /guides/old-post/ to https://example.com/guides/new-post/. Confirm the replacement is published and accessible before enabling the redirect. In WordPress, enable Redirections under SEO → PRO → Redirections / 404. Then open SEO → Redirections and add a rule. Set the origin to guides/old-post, the destination to the full new URL, the type to 301 and the login condition to All. Save the enabled rule. Keep the rule specific to that article unless you intend to move a group of URLs.

Verify the first response and the final page

Open the old URL while signed out, or run curl -sS -o /dev/null -D - https://example.com/guides/old-post/. The expected first response is 301 with Location pointing to the new URL. Request the new URL separately and check for 200. If there is an intermediate hop, check for another redirect rule, a WordPress permalink normalization or a CDN rule. If a cached response gets in the way, clear the relevant cache and repeat the two requests.

Update the references you control

Replace the old URL in internal links and check the replacement’s canonical. For an indexable article, confirm the sitemap lists the new canonical rather than the old address. If campaign parameters matter, test an old link with a sample query string and confirm the intended parameters reach the new URL. Leave the redirect in place for people using old links and avoid sending unrelated removed pages to this article.
