用 Castos 和 WordPress 发布第一集播客：核对页面、RSS 和音频

选定编辑入口和分发地址，拿一段预告走完单集页面、RSS 条目和实际收听三项检查。

先看结论

如果单集页面由 WordPress 管理，可以用 Seriously Simple Podcasting 发布，让 Castos 托管音频。对播客目录只提交一个 RSS 地址。提交前确认单集页面、RSS 里的音频附件和播放器打开的是同一集。

Castos 评测

先定下来以后在哪改每一集

准备节目名、方形封面和一段短预告 MP3。按官方快速入门在 WordPress 接入 Seriously Simple Podcasting，连到要发布的 Castos 节目。之后在 WordPress 维护单集，再同步到 Castos。官方说明直接在 Castos 后台改内容不会反向写回 WordPress。如果团队更想在 Castos 编辑，可以从后台发布，再把播放器嵌到 WordPress。

只对外分发一个 RSS

插件和 Castos 都能提供订阅源，先选定要提交给播客目录的那个，更换托管或分发设置后再复核。Castos 建议多数新节目用托管版订阅源。已有节目换托管前，先记下旧地址和重定向方案。只有打算公开时才发布公开预告；私密源交给受邀听众。

打开页面、查条目、播放和拖动进度

退出登录打开单集页，将标题对照 RSS 的对应条目，再查 GUID 和 HTTPS 音频附件地址、类型与长度。然后播放并向前拖动。11 月 10 日我们用 Castos 的公开节目 Audience 做了只读检查：目标条目有 audio/mpeg 附件，播放器可播放和跳转。同一份订阅源的其他条目发现重复 GUID。检查自己的节目时，确认各集 ID 不重复，新增第二集后再验证一次。

确认目录提交和套餐条件

发布单集以后，还要单独提交公开 RSS，并明确谁负责维护目录账号。公开样例只能证明该集可收听，自己的上传或私密听众权限还得验证。创作者账号试用流程走到绑卡页面就停了。开通前核对实际套餐和付款条款。

迁移节目之前，先决定在哪编辑每一集

Castos 官方文档列出两条发布路径：直接使用 Castos 后台，或通过 Seriously Simple Podcasting 在 WordPress 发布。一位 G2 用户喜欢从 WordPress 发布后自动同步到 Castos，另一位则希望迁移时能带走原平台的统计。换托管平台之前，先确定今后在哪编辑单集，备份历史数据，并确认 RSS 重定向怎么做。如果做的是私密播客，还要验证受邀听众能否用自己的订阅地址收听。
