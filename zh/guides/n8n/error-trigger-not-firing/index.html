n8n Error Trigger 为什么没触发？用一次自动执行排查告警

绑定错误工作流，制造一次受控失败，并用执行记录判断告警停在触发、关联还是通知环节。

作者 Evan · 更新于 2026年11月13日

先看结论

n8n 的 Error Trigger 没有触发时，先查来源工作流是不是自动执行，再查它是否绑定了正确的错误工作流。手动执行失败不会触发 Error Trigger。用一次性的测试工作流和单独的通知渠道验证。

n8n 评测

让测试工作流故意失败一次

另建一个以 Error Trigger 开头的错误工作流，把通知发到测试邮箱。能取得时，附上工作流名称和执行记录链接。在一次性的来源流程里，把 Stop And Error 接在 Schedule Trigger 等自动触发节点后，填一条容易辨认的错误消息，再在来源流程的设置中选定错误工作流并开启自动执行。

对比手动失败和自动失败

先手动执行一次，预期编辑器报错而 Error Trigger 不发通知。再等定时器自动执行一次，确认来源执行失败、错误工作流有记录，然后核对通知时间和执行记录。验收完关掉测试定时器。

根据执行记录定位断点

来源流程没有自动执行记录，就查触发器和启用状态。来源已失败但错误流程没运行，就查关联和执行方式。错误流程运行了却没有消息，就查通知节点。业务上视为失败的空结果，可能需要你在来源流程里显式判断。
