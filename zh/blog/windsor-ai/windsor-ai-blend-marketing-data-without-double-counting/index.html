Windsor.ai: 两个渠道报表一加，怎么比店铺实收还高？

用两笔订单与两家广告渠道拆解重复收入，决定何时按订单键去重，何时保留平台各自的归因报表。

作者 Evan · 更新于 2026年11月18日

把实收与渠道归因分开。Windsor.ai 的 Blended Data 连接器可以从同一入口读取已接入的数据源。制作报表时，仍需要自己决定每行代表一笔订单、一个渠道的一天，还是某广告平台归因的一笔转化。渠道报表可能同时对同一订单分配功劳，也可能使用不同回溯窗口。

用两笔示例订单核对收入

  • Windsor.ai 数据字段与 Blended Data

从 Blended Data 导出时，把 source 和日期、金额一起留下，方便追溯每行来自哪个连接器。设计合并规则前，先确认每个来源是否提供订单 ID。

用两笔示例订单核对收入
订单店铺金额渠道 A 报告渠道 B 报告
A001808080
A00250—50
合计13080130

虚构样本中，两个渠道的合计是 210，店铺订单合计才是 130。渠道 A、B 都认领了 A001。若是订单层级数据，用商店和订单 ID 一起组成键，先在订单表中校正多行商品明细、退款和币种，再统计订单销售额。不同商店的短订单号有可能重合。GA4 官方也说明了像订单编号这样的唯一交易 ID 怎样用于减少重复购买；这不能替代对多个渠道报表的去重。

  • Google GA4 交易 ID

日汇总保留各平台的独立口径

没有共享订单 ID 的广告汇总，可按日期、渠道、账户、币种和窗口分别展示。把「平台归因收入」与「订单销售额」放成不同列，账单里哪一列用来比 ROAS 也要写明。若报表还要展示媒体花费，先把订单与花费分别汇总到确实可以对齐的维度，再测试拼接会不会把一笔金额放到多行。上线前，从样本中挑一个双重归因订单，再对照退款与时区。汇总显示应能分别回答花了多少、各平台如何归因、商店实际记了多少。
