两个 n8n 流程都在整理地址，哪一段值得拆出去？

用可复用的地址字段检查定义父子流程边界、明确返回值，并区分业务不通过与流程故障。

作者 Evan · 更新于 2026年11月18日

网站提交和客服补单需要同样的地址字段检查。把「去空格、检查必填字段、把结果交回去」拆成子工作流，父工作流继续决定要不要受理、提示谁补填以及是否写入订单。只有一个流程用这几步时，先放在当前流程通常更容易看懂。第二个入口真的需要同一套输入和输出时，再提取出来。

先约定子流程说得清的事实

示例仅核对国家代码、城市和地址第一行是否存在。它只告诉父流程哪些字段可继续处理，无法保证承运商可以送达。父流程传入 requestId、countryCode、city 和 line1，子流程返回 requestId、status 和 missingFields。上游发来的交易资料不必连同地址一起传给它。

在子流程的 Execute Sub-workflow Trigger 定义输入字段。在父流程用 Execute Sub-workflow 指向它并传值；父流程后续要使用结果时，启用等待完成。n8n 会把子流程最后执行的节点数据返回给调用方。把示例中的两条业务分支整理成一致的返回字段，运行后从父流程分别打开两次结果。

缺字段让用户补，执行异常让团队查

缺城市属于正常返回，网站流程可以提示补填，而客服流程可以给同事一项待办。节点报错或执行权限没开时，保留执行错误，方便排查；如果误把所有异常都转成「缺地址」，客服看到的就是一个用户无法解决的问题。新增第三个入口时，先用同一组样例比较输出；如果它要求真实可配送验证，应以新的验证步骤承担这项任务。

预演时加一个空值案例。父流程可以把未映射字段作为 null 传入，只有空格的值也应判为缺失。两种情况用相同的结果字段返回；没有 requestId 时当作输入错误，因为父流程无法把结果对回原请求。
