同一个表单发了两次，怎样让 n8n 只建一条记录？

用稳定提交 ID 和 PostgreSQL 唯一主键处理重复 Webhook，检验并发、首次写入与后续通知。

作者 Evan · 更新于 2026年11月18日

把判重放到负责写入的数据库。假设报名表服务在网络超时时会重送同一个投稿，工作流每收到一次就创建一行，就会让一个人占两个名额。让表单系统在重送时带上原来的提交 ID，把它设为数据库的唯一键。n8n 收到数据后用 Postgres 节点执行带参数的写入，重复提交走相同的数据库规则。

把先查后写换成一次写入判断

  • n8n Postgres 节点
  • PostgreSQL INSERT 文档

为测试库单独创建表，字段 submission_id 为文本主键。示例把工作流传入的两项字段作为节点的 Query Parameters，按 $1、$2 的顺序传入。多个来源的提交 ID 可能重复时，用来源与原始提交 ID 的组合作为数据库键。不要用联系邮箱当键，同一个人可能有两次有效报名。

WITH inserted AS (
  INSERT INTO form_entries (submission_id, submission_name)
  VALUES ($1, $2)
  ON CONFLICT (submission_id) DO NOTHING
  RETURNING submission_id
)
SELECT EXISTS (SELECT 1 FROM inserted) AS created;

首次写入返回 created = true，后续同键返回 false。这个查询仍会给 n8n 返回一个明确的布尔结果，便于下一节点判断。两个执行同时先查询也可能同时看见空结果，所以由数据库主键在插入时解决竞争。另为缺 ID 的输入设一个拒绝分支，避免生成随机 ID 之后把重试当成新提交。

用三个请求检查表，再看谁收到确认

用一条虚构提交 demo-42 从测试发送端发两次，再发一个合法的新 ID demo-43。在两个相同请求同时发送的情况下也重复验证。预期表里有两行，demo-42 只出现一次。缺 ID 或不同来源使用同一 ID 也各试一次，方便发现键选错或格式遗漏。

如果后续还要发确认邮件，只允许新创建的分支触发它。数据库写入成功后、邮件发出前仍可能中断。如果确认邮件不能丢，可以先在同一事务里记录待发送事件，再让独立任务处理和重试。表里只有一行与邮件最终只送达一次是两个验收点。
