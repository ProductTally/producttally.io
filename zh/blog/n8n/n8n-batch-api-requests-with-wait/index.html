n8n 怎么用 Loop Over Items 和 Wait 分批调用 API？

把表格记录导入业务系统，同时按接收方的限额控制请求节奏。

作者 Evan · 更新于 2026年11月24日

接收方有请求限额时，可以用 n8n 的 Loop Over Items 和 Wait 给批次留出间隔，短时中断则可考虑 Retry On Fail。设置之前，先看接收方限额，再算一行数据会产生多少次请求。

n8n · 查看产品详情

先数请求次数，再数表格行数

假设团队要把 100 条已审核商品记录导入自己的目录，每条需要一次写入，API 每分钟允许写入 60 次。示例可以设每批 10 条、批次间等 15 秒，节奏大约是每分钟 40 次写入，还没算其他工作流。如果每行还要先查询一次，而查询和写入共用额度，请求量就会增加。

按目标 API 的文档确认额度按凭证、滚动窗口还是其他方式计算。给同凭证的定时流程留出空间。遇到 429，先查限额和自家流程的请求分布。

提前想好导到一半怎么接着跑

用 Loop Over Items 取一批，接发送请求的节点，经 Wait 返回循环。短时中断并且确认可以安全重复时，再用 Retry On Fail。新增记录时，如果目标支持 upsert 或稳定记录键，可以让重跑更新已有条目，避免重复创建。

每条记录单独保存一个结果，只补跑未决条目。请求超时但服务端可能已经收到时，先从目录的当前状态继续。
