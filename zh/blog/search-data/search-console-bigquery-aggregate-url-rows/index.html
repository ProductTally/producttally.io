Search Console 导出的 BigQuery 数据为什么有重复网址行？

先按报表粒度加总点击和展示，再算点击率，缺失的导出日期单独标记。

作者 Evan · 更新于 2026年11月19日

Google Search Console 的大批量导出中，同一个键可能有多行。做逐日页面报表时，先固定搜索类型，再按日期和网址分组，把点击和展示分别求和。点击率用两个总数相除。Google 的示例建议加总，保留一行会丢掉该键的部分数据。

先定义一行报表代表什么

逐日页面报表从 searchdata_url_impression 取数，固定时间窗和搜索类型。需要分国家时把 country 加入分组。做全站属性报表时可考虑属性级的表，因为 Google 给这两种表定义了不同汇总方式。核对数据集名，并把 data_date 限定在需要的范围，导出日期按太平洋时间记。

加起来，再算点击率

例如某天同一网址有两条虚构记录，一条是 20 次展示、4 次点击，另一条是 80 次展示、6 次点击。两行都保留，合计 100 次展示、10 次点击，点击率为 10%。直接平均两行的点击率会算成 13.75%。在 BigQuery 中用 SAFE_DIVIDE 除两个汇总值，分母为零时留空。

SELECT data_date, url,
       SUM(clicks) AS clicks,
       SUM(impressions) AS impressions,
       SAFE_DIVIDE(SUM(clicks), SUM(impressions)) AS ctr
FROM `my_project.searchconsole.searchdata_url_impression`
WHERE data_date BETWEEN @start_date AND @end_date
  AND search_type = 'WEB'
GROUP BY data_date, url
ORDER BY data_date, clicks DESC

缺导出的日期单列

比较两周之前，在 ExportLog 查对应表和日期。日志记录成功的导出，网址表与属性表可能不会同时入库。某天没有记录时，在报表标为数据缺失。等两个时间窗都齐了，再按同一搜索类型和分组方式比较。
