Udemy Git 课怎么选？用 README 练一次合并冲突

两条分支同时改同一句话，用状态和暂存差异确认保留了双方重要的改动。

作者 Evan · 更新于 2026年11月23日

在 Udemy 选 Git 合并冲突课程，找要求你读懂两边改动、解释最终文本的练习。团队遇到冲突时，实际要决定的是内容。你需要知道谁修改了日期，谁补充了版本，以及两者能否一起保留。

Udemy · 查看产品详情

让两条分支各自改动同一行

建一个独立的练习仓库，先提交 README，写一行「周五发布」。从这个提交分出两条分支，一条把同一行改为「周四发布」，另一条改为「周五发布西语版」，各自提交。切回第一条分支合并另一条。两边修改了同一行的不同内容，这个练习用来产生文本冲突。

发生冲突时，先用 git status 找到文件，再打开 README。冲突块用 <<<<<<<、======= 和 >>>>>>> 分开两份文本。如果已经确认西语版也改到周四，可以合成「周四发布西语版」。期限有歧义时，先向负责人确认。

  • GitHub 官方文档

看清最后要提交的版本

改好句子并清理冲突标记，执行 git add README.md，再用 git diff --cached 看暂存区里要提交的改动。确认西语版和周四都在，再用 git commit 完成合并，检查工作区状态。若团队通过 PR 审阅，在说明里写一句日期为什么变、语言版本为什么保留，让别人能复核。

Udemy 的 *Git & GitHub – The Practical Guide* 公开目录列出用 VS Code 处理冲突、用 git diff 比较改动和 GitHub PR 审阅。试听时找老师怎样核对解决后的最终内容，尤其是两边的改动都要留下的时候。
