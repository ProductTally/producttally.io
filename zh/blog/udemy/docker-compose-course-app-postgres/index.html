在 Udemy 选 Docker Compose 课，优先找要求你把应用和数据库连起来的章节。做到「浏览器能打开」以后，再确认数据在更换数据库容器后仍保留。这样选课，你能从一个项目里弄清服务名、端口和数据卷各自管什么。

两个容器都启动了，应用为什么还是连不上数据库？

假设你接到一个小团队的原型，交接只写着「开启 Docker」。可以用 Adminer 作为本机网页界面，把 PostgreSQL 服务命名为 db。浏览器从本机回环端口访问 Adminer，例如 127.0.0.1:8080。Adminer 的数据库地址填 db，这个练习无需把数据库端口映射到宿主机。Compose 默认网络中的服务可以通过服务名找到彼此。

只用独立的本地练习项目。选 PostgreSQL 17 官方镜像时，数据卷目标是 /var/lib/postgresql/data。换大版本前再确认镜像文档。Adminer 页面能打开、数据库暂时连不上时，先确认数据库是否已就绪。练习账号和密码只用于本地配置。

最后一关是把原来的记录查出来

在练习库建 notes 表，放一个文本字段 body，写入 demo entry。用 docker compose up -d --force-recreate db 重建数据库容器，保留命名数据卷。等数据库就绪后重新连上，执行 SELECT body FROM notes;，预期仍只返回一条 demo entry。如果换成了空数据卷，那是在验证另一件事。

Udemy 的 *Docker Mastery* 目录中有 Compose V2 命令、Drupal 与 PostgreSQL 的双服务作业，还有独立的镜像构建作业。当前目标是把小项目在本机跑起来，可以先看 Compose 章节。本文的 Adminer 示例是同类架构的简化练习。

可复制的 Compose 练习配置

services:
  ui:
    image: adminer
    ports:
      - "127.0.0.1:8080:8080"
  db:
    image: postgres:17
    environment:
      POSTGRES_DB: practice
      POSTGRES_USER: learner
      POSTGRES_PASSWORD: ${PRACTICE_DB_PASSWORD:?Set a local practice password}
    volumes:
      - notes-data:/var/lib/postgresql/data

volumes:
  notes-data:

在练习目录的 .env 中设 PRACTICE_DB_PASSWORD，再运行 docker compose up -d。打开 http://127.0.0.1:8080，选择 PostgreSQL，服务器填 db、数据库填 practice、用户填 learner，密码用本地设置的值。
