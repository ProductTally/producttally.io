SEOPress 的 sitemap 里出现作者、附件或私人页面，应该怎么处理？

区分作者归档、附件页和私人页面，查清入口、抓取与索引，再验证子站点地图。

作者 Evan · 更新于 2026年11月18日

先打开 sitemap 索引，再到列出该 URL 的子 sitemap，确认它究竟是作者归档、WordPress 附件页、直接媒体文件还是普通页面。不同入口需要在不同位置处理。SEOPress 文档说明，通过插件标记为 noindex 的文章或页面会自动排除在 XML 站点地图之外。已存在或可被外链找到的 URL 仍需单独核对状态。

发现的地址检查什么改完验证什么
/author/editor/作者专题是否有独立价值、是否生成作者 sitemap实际归档的响应与搜索策略；子 sitemap 不再把它当索引目标
WordPress 附件页打开的究竟是附件 HTML，还是直接图片/PDF前者按页面策略处理，后者查媒体文件的实际响应
内部报价预览从无登录浏览器能否打开访客无法读取内容，并从 sitemap 和公开链接移除

用访客看到的页面来验收

例如，同一个营销团队把一个有附件的内部报价单从 sitemap 里删了，再从旧邮件链接打开，发现文件仍可访问。这时要检查直接 PDF 或图片 URL 的权限。对公开 PDF 若只想排除搜索，可配置合适的 HTTP X-Robots-Tag，并让爬虫读取该响应。仅限内部的报价使用访问控制。改完后，再分别检查该 HTML 或文件的响应、原来的子 sitemap 和对它有链接的页面。

  • Google 的 robots meta 与 HTTP 头说明

从 SEO → XML – HTML Sitemap 提供的入口打开实际索引。在 Post Types & Taxonomies 核对哪些类型本应纳入。单独调整一页后，重新打开对应的子 XML，查找原来的完整 URL。若是直接文件，还要看它自己的 HTTP 响应。

如果旧 XML 来自缓存，就按 hosting 和 sitemap 生成方式清理。提交新的 sitemap 后，可在 Search Console 核对 URL 的当前抓取和索引状态。站点地图里消失只是第一项验收，原地址对访客和搜索引擎的表现要分别核对。
