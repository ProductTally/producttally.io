Cloudflare Search for Agents 还在返回旧文档？这样排查

沿着一条过时的检索结果，核对源网页、抓取与同步记录，再检查检索缓存。

作者 Evan · 发布于 2026年11月28日 · 更新于 2026年11月28日

Cloudflare Search for Agents 返回旧内容时，先打开结果引用的原网页，核对当前网页和返回段落，再查最近的抓取与同步。该功能于 2026 年 11 月 25 日发布 Beta 版。

Search for Agents 文档

先看它引用的是哪一页

假设桌面软件的安装说明从第 2 版更新到第 3 版。在站点的 /.well-known/search 端点输入客户会问的原话，记下查询时间、来源地址和提到第 2 版的句子。若它指向单独保留的旧版文档，再问一遍明确带有「第 3 版」的问题。这样可以分清是新版网页的索引仍旧，还是搜索找到了另一篇存档。

  • Search for Agents 文档

同步成功后，网页也可能还没重抓

Search for Agents 默认采用 Discover 抓取，抓取缓存期限为 24 小时。Discover 决定何时重抓时会忽略站点地图的 lastmod。打开实例设置和 Jobs 历史，把网页部署时间与同步任务时间放在一起看。手动同步也遵循实例的重抓规则。

  • 抓取方式
  • 索引同步任务

用原来的问题复查

确认网页内容进入索引后，再用同一个问题查询，对照来源地址和返回段落。若怀疑结果被复用，AI Search 文档说明可通过 cf-aig-cache-status 的 HIT 和 MISS 判断缓存，并指出索引片段变化或删除后，对应缓存会清除。这个端点返回检索到的段落，可以直接核对文字是否已更新。
